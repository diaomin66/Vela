# 模型评测

Vela 0.5.0 增加独立的「评测」工作区。评测调用已保存渠道的 Responses API，使用全新上下文和明确题目，不读取编程任务或执行模型生成的工具。每次结果保存题目、答案、推理档位、耗时、服务商返回的 Token 用量、题库版本和分项检查，便于复查。

## 手动评测

1. 在渠道中启用需要测试的模型，然后打开「评测 → 开始评测」。
2. 每轮选择 1–6 个模型，同名模型在不同渠道分别测试。可以给每个模型选择不同的 API 推理档位；「API 默认」表示请求中不指定 effort，不代表 Vela 原生模型目录的默认选择。
3. 选择糖果、鹈鹕和判题测试。按需指定独立评审模型，对答案增加文字复评。被测模型与评审模型相同时，会标记同模型自评。
4. 查看每项分数、原文与图像；可以随时停止后续请求。记录中未完成、超时、认证失败与格式错误分别处理，不将网络错误计成能力零分。

一次被测模型回答计一次请求；启用复评后，每个有效文本回答最多再发送一次评审请求。上限为 6 模型 × 3 题 × 2 = 36 次请求，每轮的具体上限在启动前显示，按渠道计费。没有自动重试。输出上限 8192 tokens；响应超限、未完成或只有工具调用时，该题显示未评分。

0.5.1 起在「评测计划 → 单次请求超时」配置时间，新计划默认 5 分钟，提供 2、5、10、30 分钟预设和 30–3600 秒自定义整数。每道题与独立评审分别拥有完整上限，包含等待响应头和接收响应体；连接建立上限仍为 15 秒。超时和网络中断分别提示，超时不计零分也不自动重试。运行开始时保存当轮设置，之后修改计划不影响正在执行的请求。

旧版保存的计划与历史没有此字段，按当时的 120 秒读取，保留旧记录的准确性；可以在评测计划中修改后保存。手动开始使用当前设置执行一次，保存计划才更新定时运行的设置。兼容性检测仍使用独立的 35 秒上限，不受评测计划影响。

## 题目与评分

| 测试 | 本机检查 | 解释范围 |
| --- | --- | --- |
| 糖果策略 | 返回严格 JSON 整数，参考最小保证预算为 21 | 检查该道最坏情况策略题 |
| 鹈鹕骑自行车 | 完整安全静态 SVG、有效 viewBox、可绘图形元素 | 结构分只表示文档技术条件，不评价画面是否像鹈鹕 |
| 判题能力 | 对 6 道原创答案判断题逐项比对布尔标签 | 检查这些算术、逻辑和概率答案的判断能力 |

题面和规则随结果保存。固定题库便于跨时间比较，也存在记忆题目和针对题目优化的局限，不能证明模型身份，更不能作为标准化 IQ 分数。历史比较仅对相同题库版本、渠道模型、显式推理档位和测试项目显示差值。

### 糖果题的来源与规则

参考实际维护该题型的 [MaShouo/CandyTest](https://github.com/MaShouo/CandyTest)。这不是对原题最早作者的认定。原表为圆形苹果 7、桃子 9、西瓜 8；星形苹果 7、桃子 6、西瓜 4。不同表述对能否途中观察口味、自适应调整形状存在歧义，因此 Vela 明确采用自己的澄清版本：每次能选形状，不能预知口味；取出后可观察口味并决定下一步，目标是苹果和桃子各一颗且形状不同。

答案 21 的上界：9 颗圆形必有苹果或桃子，12 颗星形必同时有苹果和桃子。下界：每种形状按最坏顺序先出西瓜、再出 7 颗苹果、最后桃子。取得一种形状的桃子并配上另一种形状的苹果，至少经过 12 颗西瓜、7 颗苹果、1 颗桃子、1 颗异形苹果，共 21 颗。测试另外用记忆化 minimax 搜索验证答案，不从生成模型答案反推参考值。

### 鹈鹕题的来源与预览

原始任务来自 [Simon Willison 的 pelican-bicycle](https://github.com/simonw/pelican-bicycle)，是绘制骑自行车的鹈鹕 SVG。Vela 附加静态文档、安全标签和 viewBox 约束。相关背景见作者的 [2025-06-06 文章](https://simonwillison.net/2025/Jun/6/six-months-in-llms/)。

后端只允许有限静态 SVG 标签和属性，拒绝脚本、事件、外链、嵌入 HTML、动画、DTD 和不受控样式。前端通过独立图片解码预览，不将模型生成代码插入页面 DOM。被拒绝的内容只作为文本显示。圆轮可以由 path 绘制，因此不以 circle 数量或标题文字判定绘画质量。

当前可选评审看到的是 SVG 源码，结果明确标记为「SVG 代码复评」。它没有看到渲染图，不能冒充视觉模型评分；实际画面请通过预览检查。

### 原创判题任务

Vela 原创六题覆盖算术、等距离平均速度、集合推理、任务排列、条件概率和 Python 表达式结果。程序按已知标签评分，不运行 Python 或其他模型生成代码。其独立题库名称与版本随记录保存，不声称是外部标准 benchmark。

## 定时与记录

定时默认关闭。选择间隔并「保存计划」后生效；手动「开始本次评测」使用当前选择执行一次，不覆盖已保存的定时设置。主页面可直接暂停定时。启用定时意味着授权按计划调用所选模型及评审模型；关闭 Vela 窗口后托盘进程仍会执行计划，完全退出后停止。

定时最多同时执行一轮，手动和定时共享同一运行名额。重启遇到过期计划只执行一轮，不积压补跑多次；中断中的旧请求不重发。计划所依赖的渠道已删除、模型停用或档位不再有效时，显示错误，不替换成其他模型。

记录独立存放在应用数据目录 `evaluations/`，最多保留 100 轮。原文有大小限制；导出包含题目、答案、公开评分结果和用量，没有 API Key 或原始鉴权头。可在结果右上角导出 JSON；桌面显示保存成功与完整路径，可直接复制。用户主动导出的报告保存在 `evaluations/exports/`，不随历史清理删除，可自行归档或移除。浏览器演示只使用内存中的模拟回答，没有真实后台调度、网络请求或持久化。

## Ultra 与评测的区别

Ultra 已作为官方 Codex 的原生多代理选项接入。它会在官方客户端中启用任务委派，并转换为实际 API effort。此页直接请求模型 API，因此仅显示确认过的 API 档位，不将 `ultra` 作为请求参数。详见 [原生 Ultra 能力与官方出处](model-capabilities.md#原生-ultra)。
