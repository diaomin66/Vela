# 界面设计规范

AhaX 是面向中文用户的 Windows 桌面工作台。六个工作区、设置和弹窗使用同一套视觉层级：先读懂对象与状态，再定位信息，最后执行操作。新增页面应复用已有组件与语义令牌，不单独定义一套字号、颜色或控件尺寸。

## 字体与阅读层级

界面文字使用 `--font-ui`，优先使用 Windows 的 Segoe UI Variable Text / Segoe UI，中文回退到 Microsoft YaHei UI / Microsoft YaHei，再回退到 Noto Sans SC。品牌字样使用 `--font-display`；需要逐字符辨认的代码使用 `--font-mono`，即 Cascadia Code / Consolas。数据路径可保持界面字体，并通过换行保证完整值可读。

| 语义令牌 | 大小 | 用途 |
| --- | --- | --- |
| `--text-page` | 28px | 工作区主标题、主要抽屉标题 |
| `--text-section` | 20px | 分组标题、设置章节、计划标题 |
| `--text-title` | 18px | 渠道、模型、线程等主要对象名称 |
| `--text-body` | 16px | 正文、输入值、搜索文字、详细结果 |
| `--text-small` | 14px | 字段标签、按钮、筛选、说明文字 |
| `--text-caption` | 13px | 时间、数量、单位、路径等辅助元数据 |
| `--text-stat` | 28px | 需要突出的关键数值 |

13px 只用于辅助信息，不能替代操作文字、重要字段或主要正文。页面标题保持 28px；窄屏优先换行和调整布局，不通过缩小标题、对象名、正文或表单字体适配。导航在窄屏采用 14px 控件文字层级。

字重仅使用以下语义令牌，避免散落 450、550、650 等局部值：

| 令牌 | 字重 | 用途 |
| --- | --- | --- |
| `--weight-normal` | 400 | 正文、说明、元数据 |
| `--weight-medium` | 500 | 导航、选项、一般对象名称 |
| `--weight-semibold` | 600 | 分组标题、字段标签、按钮、选中项 |
| `--weight-bold` | 700 | 页面主标题与品牌 |

行高同样按语义统一：`--leading-tight: 1.35` 用于标题，`--leading-body: 1.6` 用于控件与普通内容，`--leading-copy: 1.8` 用于较长说明、评测正文与版本说明。应用样式中的 `font-size`、`font-weight`、`line-height` 必须引用对应令牌，或明确继承已有值。

## 间距与控件尺寸

间距使用 4px 步进的令牌：`--space-1` 至 `--space-8` 分别是 4、8、12、16、20、24、28、32px；较大分组间距使用 `--space-10: 40px` 和 `--space-12: 48px`。同一分组内部保持紧密，章节之间保留更大的距离，不能只靠颜色或边框分组。

| 类型 | 令牌与规范 |
| --- | --- |
| 主要按钮、输入、搜索、表单下拉 | `--control-height: 44px` |
| 行内操作、小型图标按钮、分段选项 | `--control-height-sm: 36px` |
| 分段控件外框 | 至少 44px，内部选项至少 36px |
| 主要控件圆角 | `--radius-sm: 10px` |
| 内容分组圆角 | `--radius: 16px` |
| 主工作区、弹窗、抽屉圆角 | `--radius-lg: 22px` |
| 小型细节与胶囊 | `--radius-xs: 6px`、`--radius-pill: 999px` |

字体和控件高度是两项独立约束，不能通过压缩行高让按钮看似满足高度要求。渠道与设置抽屉采用 640px 标准宽度，头尾固定、内容独立滚动；窄屏缩小外侧留白并重排底部状态和动作。

## 页面结构与共享组件

`src/components/ui/Workspace.tsx` 提供三个共享结构组件：

- `PageHeader`：页面标题、可选数量、说明和操作区。标题与操作在宽屏并排，空间不足时操作换行。
- `SectionHeading`：章节标题、可选说明及辅助操作。同级章节保持相同字号、间距与对齐方式。
- `WorkspaceToolbar`：搜索、筛选和结果范围。工具栏紧邻所控制的列表，筛选与搜索保持同一控件高度。

任务子导航位于页面标题下方。评测子页面、线程范围、设置页签和结果页签复用 `segmented-control`。选中项使用统一表面、边界与字重，同时由 `aria-current`、`aria-selected` 或 `aria-pressed` 表达状态；每个单选分组只保留一个选中项。

对象列表以名称为首要信息，原始模型 ID、渠道地址、时间、路径与单位使用辅助层级。模型库只保留一套列标题，渠道分组不重复表头。概览仅展示影响下一步操作的状态、数量和范围，不挤占主要内容的首屏空间。

## 配色与状态

浅色使用中性白与浅灰表面，深色使用深石墨表面。两种主题共享结构和含义；主操作采用高对比的中性色。品牌不额外引入独立强调色，成功、警告、错误颜色仅用于相应状态。

| 角色 | 语义令牌 |
| --- | --- |
| 窗口与正文表面 | `--canvas`、`--workspace`、`--surface` |
| 辅助表面、悬停、内嵌内容 | `--surface-soft`、`--surface-hover`、`--surface-inset` |
| 浮层与可编辑表面 | `--surface-raised`、`--field` |
| 主要文字与辅助文字 | `--ink`、`--muted`、`--subtle` |
| 一般边界与可编辑边界 | `--border`、`--control-border` |
| 主动作 | `--accent`、`--accent-hover`、`--on-accent` |
| 选中状态 | `--selected-bg`、`--selected-ink`、`--selected-border` |
| 键盘焦点 | `--focus`、`--focus-ring` |

主要标题、对象名称、可编辑输入值和关键标签与实际背景的对比度至少为 7:1；辅助正文、元数据、只读字段和操作文字至少为 4.5:1。需要在浅色、深色以及选中表面分别验证。禁用控件单独表达不可操作状态，不能用低对比样式展示仍需阅读的普通信息。

`--focus` 是焦点颜色；`--focus-ring` 是完整的 `box-shadow` 值，不能将其用作 `border-color`。选中项必须有可辨认的背景、勾选或单选标记，状态必须包含文字，不能只依赖颜色。

## 表单、内容与响应式

输入框需要清楚的可编辑边界。标签在上、字段在中、说明在下，同类输入和下拉共享尺寸、圆角与焦点状态。高级设置使用可展开分组，避免在卡片中重复套卡片。保存动作在抽屉底部持续可达，错误消息紧邻相关操作，并允许长文本换行。

长名称与路径优先换行。确需省略时，完整内容必须能通过详情或明确提示读取。评测生成的 HTML / SVG 保持既有隔离边界，不强制改写模型作品的内部排版；外围标题、状态、操作和说明遵循应用规范。

1180px 与 900px 桌面宽度保持稳定导航和独立正文滚动。390px 窄屏通过工具栏换行、列布局转为纵向、操作区重排和局部滚动适配。主导航与底栏不能随正文滑走，关键动作不能因固定高度或 `overflow` 被遮挡。

## 样式责任边界

| 文件 | 责任 |
| --- | --- |
| `src/tokens.css` | 字体、字号、字重、行高、间距、颜色、尺寸与主题令牌 |
| `src/controls.css` | 共享按钮、图标按钮、搜索、状态标签与 `segmented-control` |
| `src/styles.css` | 基础排版、共享页面结构、空状态、通用弹窗与反馈 |
| `src/shell.css` | 标题栏、常驻导航、正文滚动区域与底栏 |
| `src/workspaces.css` | 渠道、模型库、配置恢复的专用布局 |
| `src/components/editor.css` | 共享抽屉、表单、模型选择、原生下拉、设置与数据位置 |
| `src/components/update.css` | 更新状态、下载进度、版本说明与更新操作 |
| `src/pages/*.css`、其他组件 CSS | 对应业务模块的专用布局，不重新定义基础视觉层级 |

页面不能覆盖全局导航、标题栏或共享组件的视觉标准。需要新增基础规则时先调整公共组件或令牌，避免依赖导入顺序覆盖同等优先级的选择器。继续使用已有原生 dialog / popover、Radix、TanStack Query 和后端服务，不另建弹窗、选择或状态管理框架。

## 回归与验收

视觉验收覆盖浅色、深色，1180×820、900×680 与 390px 窄屏。设置和模型抽屉另检查 1180px、390px 宽度下的标签、输入、选项、焦点与固定底部操作。需要实际查看有数据、空状态、长名称、长路径和错误状态；数值检查不能替代截图检查。

| 回归测试 | 约束 |
| --- | --- |
| `tests/design-system.test.ts` | 字号层级、44 / 36px 控件令牌，以及全部应用 CSS 对字号、字重、行高令牌的使用 |
| `tests/e2e/readability.spec.ts` | 六个工作区与表单的字号、7:1 / 4.5:1 对比度、控件高度、分段选中态、横向溢出、常驻导航和可达操作 |
| `tests/e2e/theme.spec.ts` | 跟随系统、主题持久化、快捷切换、首屏主题与可访问性 |
| `tests/e2e/dialog-focus.spec.ts` | 抽屉、弹窗、下拉的键盘操作与关闭后焦点恢复 |
| `tests/e2e/locations.spec.ts` | 自定义数据位置、长路径、检查与保存反馈 |
| 其他业务界面测试 | 渠道与模型、线程、评测、更新等已有工作流程 |

界面测试使用演示数据；需要原生验证时使用隔离数据目录和合成记录，不能修改真实配置、密钥、线程或安装状态。变更完成后运行对应测试，并在发布前完成界面回归与实际截图检查。
