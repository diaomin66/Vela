# 模型路由与会话

## 旧会话出现「Model is not available for this group」或 404

`ahax-` 后接 64 位哈希的是 ahaX 内部路由 ID，用于区分不同渠道里的同名模型。历史版本的 `vela-` 编号仍兼容。它们不是真实上游模型名：正常请求先到本机 ahaX，再由它读取渠道的真实模型 ID 并转发；例如上游收到的仍应是 `gpt-6-astra`。

如果第三方错误中直接出现这段编号，先检查对话绑定的服务商。已有直连会话可能仍使用原服务商，即使模型选择器后来加载了 ahaX 目录。只切换模型不会同时切换会话的服务商。新版本保留旧编号兼容，但改名前缀本身不能解决绕过本机网关的问题。

继续已有直连会话：

1. 在模型选择器中选择原服务商支持的真实模型名，例如 `gpt-6-astra`。
2. 若选择器只有统一目录项，先使用原服务商的配置与模型目录，完全退出并重新打开客户端，再继续原会话。
3. ahaX 模型库每一行都显示原始模型 ID；渠道备注不替代这个 ID。保留会话历史，不要通过修改历史 JSONL、SQLite 或删除索引来试错。

使用 ahaX 统一模型库创建后续会话：

1. 确认渠道中保存的是服务商提供的真实模型 ID。
2. 在模型库预览并应用统一目录，使配置里的服务商和本机网关一起生效。
3. 重新打开 Codex，并新建对话。旧对话不会仅因模型切换而自动迁移服务商。

若全新会话也出现此错误，在「诊断」检查服务商与模型目录是否对应本机网关，以及渠道设置是否误填了内部编号。ahaX 会在渠道保存、兼容性检测与网关转发前拒绝将内部编号作为上游模型，避免发送无效请求。

本地诊断识别受管路由或自有目录与服务商不匹配的情况，并提供统一目录修复预览。直连接入只移除 ahaX 自己生成的目录引用，保留用户自定义目录。修复配置不会改写已有会话的消息或强制迁移其服务商。

## 评测超时

0.5.0 的评测每次请求固定为 120 秒。0.5.1 在「评测计划 → 单次请求超时」提供 30–3600 秒配置，新计划默认 300 秒；旧计划和历史保留原 120 秒。保存计划后定时运行使用新设置，手动开始只应用于本轮。

ahaX 的兼容性检测另有 35 秒上限。服务商自行中止、返回限流或错误时，本地延长评测超时不会改变上游响应。
