# 模型路由与会话

## 出现「模型 vela-… 无可用渠道（distributor）」

`vela-` 后接一段哈希的是 Vela 内部路由 ID，用于区分不同渠道里的同名模型，不是真实上游模型名。正常请求先到本机 Vela，再由它读取渠道的真实模型 ID 并转发；例如上游收到的仍应是 `gpt-6-astra`。

如果第三方直接收到这段路由 ID，先检查对话绑定的服务商。一个已有的直连对话可能仍使用原服务商，即使模型选择器后来加载了 Vela 目录。只切换模型不会把该对话的服务商一并改为 Vela。

使用 Vela 统一模型库：

1. 确认渠道中保存的是服务商提供的真实模型 ID。
2. 在模型库预览并应用统一目录，使配置里的服务商和本机网关一起生效。
3. 重新打开 Codex，并新建对话。旧对话不会仅因模型切换而自动迁移服务商。

若当前使用的是直接连接第三方的配置，应选择该服务商支持的真实模型名；不要把 Vela 路由 ID 当成第三方模型 ID 填入。需要继续旧对话时保留原服务商可用的模型，不要修改会话数据库来强行迁移。

0.5.1 的本地诊断会识别已知 Vela 路由或自有目录与服务商不匹配的情况，并提供统一目录修复预览。旧版直连操作会移除当前配置中由 Vela 生成的目录引用，保留用户自定义目录；统一接入同时更新当前 profile 的目录引用。修复配置只影响之后按该配置创建的会话，不会改写已有会话。

## 评测超时

0.5.0 的评测每次请求固定为 120 秒。0.5.1 在「评测计划 → 单次请求超时」提供 30–3600 秒配置，新计划默认 300 秒；旧计划和历史保留原 120 秒。保存计划后定时运行使用新设置，手动开始只应用于本轮。

Vela 的兼容性检测另有 35 秒上限。服务商自行中止、返回限流或错误时，本地延长评测超时不会改变上游响应。
