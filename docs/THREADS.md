# 线程保护与找回

AhaX 0.8 增加独立的线程保护系统。打开应用后会识别当前 `CODEX_HOME`（未设置时使用用户目录下的 `.codex`），扫描活动与归档记录，并在自己的数据目录内建立加密保护副本。关闭窗口后，保护随托盘服务继续运行；彻底退出应用或电脑关机期间不会产生新快照。

## 日常使用

1. 打开「线程」，检查已有备份、可找回数量及最近保护时间。
2. 使用名称、项目路径或线程 ID 搜索记录。清单由后端分页读取，不把所有正文送入界面。
3. 在详情中查看来源、原服务商、完整性与备份信息。原始记录完整且属于当前数据目录时，可「在 Codex 打开」，进入原生线程。
4. 「保护设置」可启停自动保护，自定义 15–3600 秒间隔，并选择是否保护归档记录、是否在配置变更前创建保护检查点。

默认每 60 秒检查文件变化，启动后补扫；手动重新扫描会完整复核内容，后台对未变化记录使用元数据缓存并至少每 24 小时重新校验。源文件正在写入时保留完整行前缀，界面显示等待保护，不把末尾半行当成可自动修复的完整记录。

线程 ID、服务商和原始消息都不会因切换 AhaX 渠道而被批量改写。配置恢复与线程恢复使用独立存储。

## 找回记录

### 原始文件缺失，但存在保护副本

进入记录详情，选择「预览找回」。AhaX 会验证快照、原来源目录、目标位置和现有内容。确认后将完整副本写回原位置，并重新扫描。支持逐条找回和批量预览后找回；批量中失败的记录会保留，供重新预览处理。

- 目标不存在：暂存完整内容、同步到磁盘，再以不覆盖语义发布。
- 目标已有相同内容：无需重复写入。
- 目标已有不同内容或预览后发生变化：停止该项，保留双方内容。
- 最新副本损坏但存在较早完整副本：明确提示使用较早副本。无法通过校验的内容不会作为成功恢复结果。

找回文件后，可以重新打开官方客户端检查列表。归档、项目、来源和服务商筛选仍可能影响列表可见性。

### 线程引用另一份历史记录

部分新格式线程通过 `history_base` 引用已有历史。AhaX 按原始 rollout 标识追踪同来源依赖，不把逻辑线程 ID 相同的其它文件误当成所需历史。缺少基础记录、只有尚未恢复的基础副本或存在引用循环时，清单会显示待处理，不宣称完整保护。

先找回基础记录，再重新扫描并恢复引用它的线程。恢复预览会核对依赖的记录序号、字节边界及内容；预览后基础记录发生变化，需要重新预览。批量找回不会越过依赖校验，也不会自动改写多个线程文件。

Windows 下恢复期间会锁住已验证的基础文件以避免被替换。基础文件仍在写入时，需要结束相关任务后重试。依赖记录单行超过 8 MiB 时保留快照，但暂不自动恢复；这是依赖前缀验证的单行边界，不是普通线程快照的文件大小上限。

### 文件存在，但官方列表不可见

先查看记录详情中的列表索引状态。名称索引 `session_index.jsonl` 缺少一行并不等于线程丢失。

在「数据来源」中选择「重新索引」。AhaX 会先完成线程保护，并通过 SQLite 在线备份保存官方索引的一致性副本，再调用本机官方线程服务，分别核对活动与归档记录，取消服务商筛选。AhaX 不直接写入官方 SQLite 表，不发送模型请求。官方服务会依据其自身版本处理元数据与迁移。

如果本机服务缺失、不兼容、配置无法加载、索引备份失败或仍有线程正在写入，操作会明确失败，已完成的保护副本保留。未知数据库结构保持只读，不通过删除数据库来碰运气。

### AhaX 自己的保护清单损坏

选择「从保护副本重建清单」。原有数据库与日志会保留，再从独立加密清单和数据分块重建。该操作不会重建官方客户端的列表索引。个别坏副本会被隔离报告，不应阻止其它健康记录找回。

## 保护数据

默认位于 `%LOCALAPPDATA%\Vela\data\threads`。旧目录名用于兼容升级；可通过现有 `VELA_DATA_DIR` 指定另一数据目录。

| 内容 | 用途 |
| --- | --- |
| `inventory.sqlite3` | AhaX 的可重建线程目录、来源、状态和设置 |
| `catalog.bin` | 加密来源与设置副本 |
| `objects/` | 以 SHA-256 寻址的加密数据分块 |
| `manifests/` | 独立加密快照清单，保留来源、原路径、大小和校验值 |
| `restores/` | 加密恢复事务记录，用于重启后的状态检查 |
| `metadata/` | 显式重新索引前的名称索引及 SQLite 在线快照 |

数据分块和快照清单使用当前 Windows 用户的 DPAPI 加密。目录数据库保存名称、路径和状态等本机元数据，不保存完整消息正文或渠道密钥。已有完整快照不会因为源文件消失而自动删除，也没有按评测记录数量轮转清理的策略。

## 能力边界

- 这是本地保护系统。快照与原文件在同一硬盘时，不能抵御整盘损坏；需要跨设备灾备时应另行备份整个保护目录并保留 Windows 用户加密材料。
- DPAPI 副本通常只能由创建它的 Windows 用户解密，不是可直接移交给另一账户的导出包。
- 在第一次成功保护之前就已永久删除，且其它位置没有副本的消息，无法仅凭索引还原。
- 远程主机、云端线程和未登记的其它目录不在当前本地扫描范围。显式设置 `CODEX_HOME` 后不会额外扫描默认用户目录。
- 源目录离线、权限失败、链接路径、未知格式与损坏记录会单独显示。不会把暂不可访问的来源误报为线程已删除。
- 大日志使用流式哈希和分块保护；详情正文只读取有限预览。目录扫描有 20 万条目录项和 12 层递归边界，超出会显示未完成提示，而不是显示全部保护成功。
- 只有经过加密落盘、完整性校验并提交目录的内容，才会显示已保护。写盘失败、快照损坏、未完成尾行和来源变化都有独立状态。
- 文件已成功写回并通过校验后，如果后续清单刷新失败，会说明文件已恢复及需要刷新，不把已落盘的恢复误报为失败。事务状态由重启审计继续核验。
