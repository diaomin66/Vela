# 自定义数据位置

在「设置 → 数据位置」中输入完整路径，或使用 Windows 文件夹选择器选择目录。留空恢复该项的默认规则。

| 设置 | 用途 | 默认规则 |
| --- | --- | --- |
| Codex 数据目录 | 官方 `config.toml`、活动与归档会话所在位置 | `CODEX_HOME`，否则当前用户的 `.codex` |
| 索引数据库目录 | 官方 SQLite 索引与历史数据库 | 遵循现有 `sqlite_home` 配置，未配置时跟随官方数据目录 |
| 配置备份目录 | ahaX 创建的配置快照 | 应用数据目录下的 `backups` |
| 评测数据目录 | 评测计划、报告与产物 | 应用数据目录下的 `evaluations` |
| 导出目录 | 主动导出的评测文件 | 评测数据目录下的 `exports` |
| 线程保护目录 | 加密快照、来源清单、恢复与回收站记录 | 应用数据目录下的 `threads` |
| 线程索引目录 | ahaX 可重建的线程 SQLite 清单 | 跟随线程保护目录 |

`CODEX_HOME` 与 `CODEX_SQLITE_HOME` 是显式启动覆盖，界面会显示其来源并禁用相应路径输入。需要修改它们时应调整启动环境，避免隔离实例意外访问默认用户数据。ahaX 调用本机线程服务时使用相同的已解析路径。

配置文件名称仍为 `config.toml`。更改「Codex 数据目录」选择的是其根目录，不会另造一份官方客户端不认识的配置文件名。

## 保存与生效

1. 点击「检查位置更改」，查看当前位置、目标位置与将复制的文件数量。
2. 确认后保存。当前运行仍使用原来的目录，不在评测或后台保护过程中热切换。
3. 从系统托盘完全退出 ahaX，再次打开。关闭窗口只会隐藏到托盘，不等同于重启。
4. 应用在启动后台任务前复制并校验 ahaX 数据，成功后统一启用新位置。旧目录保留。

官方配置和会话目录只切换访问位置，不会随这项设置自动搬家。官方 Codex 也需要使用相同的目录设置；只修改 ahaX 的位置不会改变外部程序的启动环境。已有登记的历史线程来源继续保留。

迁移使用暂存文件、完整性校验与不覆盖发布。目标中存在不同内容、目录重叠、来源正在写入、路径包含目录联接或权限不足时，应用会显示原因并保留旧数据。线程清单数据库使用 SQLite 在线备份，包含已提交的 WAL 内容。

恢复默认位置时，如果旧目录中的同名文件与当前数据不同，也会阻止切换；请改选新的空目录，ahaX 不会自动合并或覆盖两份历史。

## 身份与备份

渠道列表、凭据引用、更新偏好和位置设置保存在固定的应用身份目录中。默认是 `%LOCALAPPDATA%\ahaX\data`。Beta 1 会校验并迁移旧默认目录，源数据保留；自定义路径继续按原设置使用。移动大体积的评测与线程存储不会更换网关身份。

高级或便携启动仍可使用 `AHAX_DATA_DIR` 指定独立的身份目录。它代表另一个隔离实例，不能当作已运行实例的数据迁移开关。

线程保护副本使用创建它的 Windows 用户加密材料。更换保存磁盘不会把它变成跨账户可直接读取的导出包。需要灾备时，应备份完整保护目录，并保留该 Windows 用户的加密材料。
