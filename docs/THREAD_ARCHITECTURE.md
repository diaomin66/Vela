# 线程子系统架构

本系统独立实现来源发现、证据分类、持久快照与恢复流程。运行模型的网关缓存不参与线程耐久存储，也不通过记录网关请求重建对话。

## 分层

```text
app/threads.rs             薄 IPC；阻塞池隔离文件与加密工作
threads/mod.rs             单实例后的惰性初始化、操作串行化、保护调度
threads/types.rs           持久化及 IPC 契约
threads/scan.rs            来源对账、增量策略、状态计算
threads/scan/files.rs      路径边界、目录发现、稳定读取
threads/scan/parsing.rs    有界 JSONL 元数据和详情解析
threads/scan/streaming.rs  大文件流式验证与完整行前缀哈希
threads/scan/dependencies.rs 同来源历史依赖图与前缀验证缓存
threads/scan/state.rs      已知官方 SQLite schema 的只读适配
threads/scan/redaction.rs  详情与标题中的常见凭据脱敏
threads/storage/paths.rs   路径/来源身份与重解析点检查
threads/storage/vault.rs   加密分块、清单、完整性和无覆盖发布
threads/storage/inventory.rs  自有 SQLite 目录、分页、重建和启动补偿
threads/storage/restore.rs    预览令牌、恢复日志、发布与重启审计
threads/storage/dependencies.rs 历史基础闭包、序号/字节边界与预览内容复验
threads/client.rs         本机官方线程协议；不提供 turn/delete/auth RPC
threads/reconcile.rs      显式索引刷新前的一致性备份与协议调用
```

前端复用 React、TanStack Query 和 Radix Dialog。概览不携带全量线程，分页上限为 100 条，详情按需读取。主题沿用现有语义色，导航固定，模态框具有焦点管理与键盘关闭。

## 身份与证据

来源 ID 由规范化绝对目录生成。逻辑线程以来源与 thread ID 识别；每份 rollout 证据另以来源与相对路径生成稳定 key。这样同一线程的历史 rollout、归档移动和不同来源中的相同 UUID 不会互相覆盖。

读取顺序不意味着修改权限。JSONL 原始记录是保护对象；名称旁路索引用于标题补充；已知 state DB 仅提供当前选中 rollout 的额外证据。数据库损坏或未知 schema 不阻止文件发现。正文解析不改变线程 ID、原始 provider 或未知字段。

`history_base` 按同来源 immutable rollout ID 建立依赖关系。扫描标识缺失基础文件与依赖循环，并保留物理快照。恢复从选中快照的实际首条元数据重新解析依赖闭包，对每份基础文件验证所需记录前缀、序号与可选字节边界，预览令牌包含依赖前缀哈希；Windows 执行期间持有只共享读取的文件句柄，避免校验后基础文件被修改或替换。

## 快照提交

1. 检查普通文件、目录边界和重解析点；记录读取前的文件状态。
2. 读取或流式验证，计算原始字节哈希，识别完整行边界。
3. 比较文件句柄与路径在读取后的大小、修改时间，变化时标记待保护。
4. 以 1 MiB 分块加密；相同来源内相同哈希复用对象，每次新对象发布后验证。
5. 完整对象先 `sync_all` 再无覆盖发布；完整加密清单最后发布。
6. 再次检查源文件是否变化，随后在自有 SQLite 的事务中提交目录，使用 WAL 与 `synchronous=FULL`。

快照对象独立于目录数据库。若进程在清单写入后、目录提交前中断，启动会发现未提交清单并补入。旧快照不按固定条数静默删除。损坏副本保留，健康副本继续可用。

## 恢复事务

预览令牌绑定来源、线程、快照内容和目标状态。执行时重新读取这些证据，而不信任前端提交路径。目标仅能位于已登记来源的 `sessions` 或 `archived_sessions` 内。

恢复先记录事务，再向同目录唯一暂存文件流式写入并同步。发布操作不覆盖目标；发布后复核目标哈希，再标记完成。Windows 路径转换支持长路径与 UNC。目录联接、符号链接、路径穿越和目标出现并发新内容都会拒绝该项。

启动审计不猜测用户意图、不自动覆盖。它核对 prepared/published 事务中的目标和暂存状态，已发布完整目标可确认为完成，中断或冲突保留文件并提示重新预览。写入部分失败不删除独立保护副本。

发布并验证成功是恢复完成的边界。之后事务状态写入失败仍保留此前的 prepared/published 证据，由下次启动核验；目录刷新失败则作为警告返回，避免用户重复恢复已经完整写回的文件。

## 生命周期

- 状态在桌面单实例仲裁之后注册，避免第二次启动干扰运行中的任务。
- 惰性初始化、加密、扫描和恢复在阻塞池执行，窗口事件循环不承担文件处理。
- 服务操作锁串行化扫描、恢复和设置；运行状态锁只保护短时状态读取。
- 关闭窗口继续托盘运行；彻底退出停止调度。未完成事务由下次启动审计。
- 自动保护默认 60 秒，可配置 15–3600 秒；增量扫描至少每天做一次内容复核，手动扫描完整核验。
- 配置应用、网关接入、配置修复和配置恢复先经过独立线程保护检查点，再执行原有预览哈希检查。

## 官方互操作

重新索引前，通过只读连接和 SQLite online backup 保存包含 WAL 已提交数据的一致性快照，验证后加密。不会仅复制 `.sqlite` 主文件，也不会执行自制 SQL 写入官方表。

协议客户端只握手并分页调用 `thread/list`；分别检查归档与非归档，移除 provider 过滤，覆盖已知来源类型。旧公开 schema 不识别新的来源枚举时只对该字段做受控兼容重试。全局截止时间、单次响应上限、分页边界、重复游标和退出清理都独立处理。不调用模型 turn，不重试付费请求。

原生打开通过官方 `codex://threads/<thread-id>` 链接，参数只来自经过 UUID 验证的本机记录。来源必须与当前数据目录一致。链接导航与快照恢复分开，历史版本仍由官方当前索引选择。

## 验证

自动化全部使用临时目录及合成记录。包含长路径、来源离线、首次空目录、半行写入、压缩文件、历史 rollout、数据库 schema 不匹配、缺失或损坏目录、快照损坏、旧副本回退、原子发布前后中断、预览后目标变化、分块去重与大量记录分页。

官方互操作用例需显式指定 `AHAX_TEST_APP_SERVER`，在隔离 `CODEX_HOME` 中执行：保护 → 删除合成源 → 恢复 → 官方列表识别 → `thread/read` 确认历史内容相同。不会打开真实用户线程或读取真实凭据。桌面烟雾测试入口为 `scripts/threads-native-smoke.mjs`。
