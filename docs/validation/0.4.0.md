## 模型与官方客户端

能力注册表记录 51 个型号组、83 个精确 ID，其中缺少完整公开档位证据的型号明确标为未证实，不自动生成推理选项。逐项官方出处、API 默认和客户端初始选择的区别见 [模型能力表](../model-capabilities.md)。

官方 CLI 测试使用从 OpenAI GitHub Release 下载并核对 SHA-256 的 0.160.0 独立可执行文件，不替换机器上已安装的客户端。测试读取与 Vela 相同结构的本机模型目录，检查 `model/list`，然后对本机模拟 Responses 服务逐档发送请求，确认未改写 effort。

覆盖 GPT-5.4 的 `none` 默认、GPT-5 Pro 仅 `high`、不配置推理的普通模型，以及 GPT-5.6 Sol、GPT-6 Astra、GPT-6 Luna、GPT-6.1 Sol 的支持集合和默认选择。全部最新档位保留 `max`。该测试是官方客户端协议验收；Vela 安装包的网关和实际目录另由原生测试覆盖。

## 原生安装包

本机以 `desktop:build` 构建签名 NSIS，提取其中的应用，在没有 Vite 的情况下运行。测试为每次执行创建独立 `CODEX_HOME` 和 `VELA_DATA_DIR`，只对这些目录应用和恢复配置。

检查包括：双渠道同名模型各自路由、根地址与 `/v1` 规范化、原始余额单位、原生目录档位、模型默认值、`max` 原样转发、JSON 与 SSE、Windows 凭据读取、本地 Token 与 Origin 校验、跨渠道续传拒绝、关闭窗口后后台可用、单实例唤回窗口、过期预览拒绝、精确恢复配置。更新 IPC 能读取当前版本、关闭自动下载并原子保存独立偏好，且不修改接入配置。

## 更新与发行

测试专用无窗口探针使用正式打包公钥和 `requireSignedVersion`，通过同一 updater 插件下载并验签。正常安装包通过；修改一个字节后拒绝；保持安装包不变、将更新清单版本改成 99.0.0 后同样拒绝。

Git 标签发布工作流在 Windows MSVC 环境重新检查版本、运行单元测试、构建签名安装包并上传 Release。公开发行包应以 Release 的 `SHA256SUMS-0.4.0.txt` 为准；本机 GNU 构建和 CI MSVC 构建不保证字节一致。发布后使用 `node scripts/updater-smoke.mjs --public` 核查真实 GitHub 下载与验签。

正式发布已于 2026-10-03 完成。GitHub Actions 再次通过类型检查、29 项前端测试与 106 项 Rust 测试。公开安装包为 **10,265,016 字节**，SHA-256 为 `ea78f93effde4edeb841e32551c102aeede0511aef6a30651aec667f322aaf28`，与 GitHub asset digest、发行校验和以及实际 updater 下载结果一致。

对公开 MSVC 安装包再次提取并运行原生验收，全部通过；额外启用 `VELA_SMOKE_PUBLIC_UPDATE=1`，通过程序实际 IPC 检查公开更新源，结果为 `latest`。全程没有执行安装或替换当前用户安装。

## 尚未覆盖

本机模拟服务不能替代真实第三方 API 验证；各渠道是否开放 `max`、余额口径和复杂工具调用需要实测。尚未在干净 Windows 虚拟机完整走首次安装、未登录引导及真实覆盖升级；更新探针不会运行安装器。当前 NSIS 提供更新包签名，但未配置 Windows Authenticode 代码签名。
