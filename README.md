# Vela · 维拉

Windows 上的 Codex 渠道、模型与配置助手。安装后从桌面打开，添加第三方 API 地址和 Key，发现并启用模型，再将统一模型库接入官方 Codex。日常编程任务仍在官方客户端中完成。

当前版本：**0.4.0 Beta**。面向日常使用的 Windows 桌面工具，包含渠道、模型库、诊断、恢复四个工作区，以及内置签名更新。用户不需要安装 Node.js、Rust 或开发工具。

[下载最新版](https://github.com/diaomin66/Vela/releases/latest) · [模型推理能力与官方依据](docs/model-capabilities.md) · [发布说明](docs/releases/0.4.0.md)

## 安装与使用

1. 从系统托盘退出已运行的 Vela，下载并双击 `Vela_0.4.0_x64-setup.exe`，安装后从桌面或开始菜单打开。
2. 添加渠道名称、API 地址、API Key。点击「拉取模型与余额」保存渠道并读取元数据。
3. 启用需要的模型，也可手动添加模型 ID。点击模型右侧的设置入口，修改显示备注、推理档位和默认强度。自动发现的新模型默认不启用。
4. 在「模型库」预览并接入 Codex。模型显示为 `渠道名称（模型 ID）`；填写备注时为 `渠道名称 · 备注（模型 ID）`。
5. 重新打开官方 Codex，使其读取统一目录；在其原生选择器中切换模型和可用的推理强度。建议先对实际使用的每个模型执行兼容性验证，再运行真实任务。

支持 Responses API 的服务商；仅支持 Chat Completions 的服务不能直接替代。模型接口列出的模型也不等于通过了 Responses、流式输出或工具调用验证。

窗口关闭后 Vela 保留在系统托盘，可以重新打开或完全退出。Codex 的凭据命令在需要时能唤醒 Vela 后台；配置引用的安装路径需要持续存在。**卸载前先在恢复页面恢复接入前的配置。** 安装器会保留用户渠道资料及加密备份。

安装器会检测 WebView2，缺少时通过安装引导程序联网补齐。当前安装包未做代码签名。

## 0.4 的主要变化

- 内置软件更新：后台检查 GitHub Release、自动下载并校验签名；准备好后由用户选择安装时间，设置中可关闭自动下载。
- 更新签名绑定版本，拒绝篡改安装包或版本不一致的元数据。发布流程可通过 Git 标签自动构建和上传安装器。
- 按官网逐型号整理推理能力与默认值，覆盖 GPT‑5.6、GPT‑6、GPT‑6.1 系列并支持 `max`；不再把不同模型统一套为四档。
- 模型库按渠道组织，突出模型名称、推理能力、默认状态和常用操作，减少重复说明；导航常驻，内容区独立滚动。
- 渠道和设置使用圆角抽屉，标题和底部操作固定。模型列表按需展开单个模型的设置，避免每行堆叠输入框。
- 统一圆角选择列表，支持搜索、键盘操作和选中状态；弹出层不会被抽屉或滚动容器裁剪。
- 模型目录提供原生推理档位和默认强度。后台保留 Codex 请求中的推理参数，按所选模型和渠道转发。
- Rust 后端按桌面协调、业务操作、存储与网络能力拆分；配置检查、凭据、备份和恢复规则继续共用。

## 推理强度

进入渠道的「管理模型」，展开对应模型设置；也可从模型库打开该模型的设置。推理档位支持自动识别、不支持、常用组合和自定义。自定义可选择原生档位：`none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`。`xhigh` 显示为「超高」，`max` 显示为「最高」。

**自动识别只匹配内置能力清单中已知的精确模型 ID。** 服务商自定义别名、带渠道前缀或额外后缀的名称不会仅凭相似名称获得推理档位；请依据该服务商实际能力手动配置。模型发现接口返回一个名称，也不代表它支持某个推理强度。

完整能力表及官网来源见 [模型能力表](docs/model-capabilities.md)。`max` 需要支持新协议的官方客户端（CLI 0.138 起可读取，建议使用当前版本）；0.137 不能读取包含 `max` 的目录。`ultra` 是客户端多代理策略名称，不能直接当作公开 API 的推理强度透传。服务商是否开放 `max` 仍以其实际接口为准。

Vela 中的「默认强度」用于生成该模型的目录默认值；Codex 会话中的原生强度选择决定当前任务使用的档位。两者用途不同：不需要为了每次切换强度回到 Vela，也不会因一次会话内切换就修改渠道设置。后台会保留请求中的强度参数，不把每次请求强制改为 Vela 默认值。

**修改模型、推理档位或默认强度后，先保存渠道，再在模型库预览并更新 Codex 配置，最后重新打开 Codex。** 保存渠道本身不会直接覆盖已应用的配置。选择「不支持推理强度」会使该模型不提供档位选择。

## 软件更新

启动 15 秒后自动检查，此后每 6 小时检查 GitHub 的最新正式 Release。默认自动下载新版本，只有签名和版本校验通过后才显示「安装并重启」。关闭窗口后更新检查仍可在后台进行，安装始终需要用户点击。

「设置 → 软件更新」可以手动检查、查看进度与更新说明，或关闭自动下载。更新偏好即时保存；下载内容保存在当前进程内存，退出后会释放。安装会短暂中断本地转发，请先结束正在运行的任务。

从 0.3 及更早版本首次升级到 0.4 需要手动安装一次。之后可使用内置更新。签名密钥只用于发布流程，渠道 Key 不参与更新请求。开发与发布步骤见 [RELEASING.md](docs/RELEASING.md)。

## 渠道、模型与后台

- 多渠道模型统一出现在 Codex 的模型目录中。本地只提供一个默认名为 `Vela` 的服务商入口；显示名称与端口可以在设置中修改，内部路由标识不展示在 Vela 的模型列表中。
- 自动识别根地址、`/v1` 和误填的 `/responses`、`/models` 后缀。路径探测只在同一服务商内进行，不跟随重定向；鉴权失败、限流会停止回退。
- 读取常见模型接口及 New API、legacy billing 余额接口；支持自定义同源余额路径、JSON 字段、倍率与单位。原始额度显示为「额度」或「站点计费单位」，不会擅自当作美元。
- 不支持余额查询时明确显示；临时失败保留上次有效数值并标记。自动刷新默认每 15 分钟，仅发送元数据 GET，不发送生成请求。
- 模型库支持搜索、按渠道筛选、逐模型验证和设置默认模型。同名模型在不同渠道有独立路由，不会串用 Key。
- 本地网关转发 Responses、流式 SSE 和 compact；关闭界面继续运行。只监听 `127.0.0.1`，每个请求都需要独立本机凭据，拒绝带浏览器 Origin 的请求。
- 配置写入仍经过预览、冲突检查和 DPAPI 加密备份；模型目录使用不可变历史文件，恢复时检查渠道、目录与凭据是否仍可使用。
- 兼容已有渠道资料，保留原 ID 和 Key；0.1 的单模型会迁移为启用模型。从旧版升级后，预览并更新统一目录以使用新的推理配置。

## 凭据、网络与恢复

渠道 Key 只保存在当前 Windows 用户的凭据管理器中，目标名为 `Vela/connection/<UUID>`。前端不会收到保存后的 Key。独立的本地网关 Token 同样存于系统凭据库，并按应用数据目录隔离。Codex 使用 `--gateway-credential` 获取该 Token，第三方 Key 由后台按路由读取。

应用数据默认位于 `%LOCALAPPDATA%\Vela\data`。`VELA_DATA_DIR` 可指定其他绝对目录，各自维护单实例；默认目录继续兼容旧版实例标识。配置目录遵循 `CODEX_HOME`，默认用户 `.codex`。备份采用当前用户 DPAPI 加密，不是跨机器迁移文件。

配置写入保留无关字段和注释，不修改官方登录资料。预览包含配置、渠道与设置版本检查，其他程序修改文件后需重新预览。已保存渠道的 API 地址不能原地替换；更换服务商请新建渠道，避免旧会话把更新的凭据发给旧地址。

本地诊断默认不发送网络请求。手动或定时元数据同步读取服务商模型与余额。点击兼容性验证最多发送三次小型生成请求，可能产生服务商费用，不执行本机工具。网关不会自动重试付费 POST 请求。

`previous_response_id` 绑定发行渠道，最多保存 4,096 条、6 小时；重启后不持久化。未知、过期或跨渠道续传返回明确错误，需要开启新会话。使用完整 `input` 的请求不依赖此映射。

## 开发

技术栈：Tauri 2、React 19、TypeScript、Vite、Rust、Axum、Reqwest。字体随程序打包，不从第三方字体服务加载。

```powershell
npm install
npm run dev
npm run typecheck
npm test
npm run test:e2e
npm run desktop:build
```

浏览器预览默认地址为 `http://127.0.0.1:1420`，使用明确标记的内存演示数据；不读写本机配置、不保存真实 Key、不发送服务商请求。请只输入虚拟密钥。

标准 Windows 构建需要 Rust、MSVC C++ Build Tools、Windows SDK、Node.js 22.12+、WebView2。此工作区也提供进程级隔离 GNU 工具链脚本，不修改系统 PATH：

```powershell
.\scripts\windows-toolchain.ps1 -Command cargo -Abi gnu test --manifest-path src-tauri/Cargo.toml
.\scripts\windows-toolchain.ps1 -Command npm -Abi gnu run desktop:build
```

发布可执行文件必须由 `desktop:build` 生成，以嵌入前端资源。不要用普通 `cargo build --release` 覆盖后直接分发。NSIS 安装包位于 `src-tauri/target/release/bundle/nsis/`。

## 后端结构

`app.rs` 只组装 Tauri 应用和注册命令，`core.rs` 提供业务类型与操作入口。具体责任分配如下：

| 位置 | 责任 |
| --- | --- |
| `src-tauri/src/app/commands/` | 渠道、配置和诊断 IPC，接收参数并调用业务操作 |
| `src-tauri/src/app/state.rs`、`runtime.rs`、`metadata.rs` | 运行状态、网关生命周期、应用目录切换与定时元数据刷新 |
| `src-tauri/src/app/updater.rs`、`updater/state.rs` | 签名更新、下载与安装协调、独立更新状态和偏好 |
| `src-tauri/src/app/desktop.rs`、`credentials.rs`、`dashboard.rs`、`inspection.rs` | 托盘与窗口、凭据命令、界面数据与环境检查 |
| `src-tauri/src/core/domain.rs`、`profiles.rs`、`store.rs` | 数据模型、渠道操作、持久化与兼容迁移 |
| `src-tauri/src/core/configuration.rs`、`changes.rs`、`backups.rs`、`repair.rs` | TOML 编辑、变更预览、冲突检查、加密备份、恢复与修复 |
| `src-tauri/src/core/paths.rs`、`filesystem.rs` | 路径边界、受限读取与原子写入 |
| `src-tauri/src/catalog.rs`、`reasoning.rs` | 官方模型目录、稳定路由 ID、推理能力策略与校验 |
| `src-tauri/src/discovery.rs`、`gateway.rs`、`diagnostics.rs`、`security.rs` | 元数据发现、请求转发、兼容性检查、系统凭据与 DPAPI |

桌面层通过业务操作执行修改，存储实现保留在 `core` 内部；互斥、版本检查、备份与原子写入由对应业务入口负责。前端的抽屉、选择控件和模型设置也分别放在 `Drawer.tsx`、`Select.tsx`、`ModelSelection.tsx`，便于独立维护。

## 验证与范围

0.4.0 已通过 **106 项 Rust 测试、29 项前端单元测试和 21 项浏览器交互测试**。签名 NSIS 提取程序通过原生 UI、凭据、双渠道 JSON/SSE、更新偏好和恢复验收；官方 CLI 0.160.0 通过 7 种模型、35 次本机模拟请求的档位及默认值检查。签名更新测试确认正常包通过、篡改包和版本错配包被拒绝。详细范围见 [验收记录](docs/validation/0.4.0.md)。

- Rust 测试覆盖配置保留、迁移、冲突、DPAPI 恢复、余额单位、同源回退、取消、鉴权、双渠道路由、即时 SSE、UTF-8 分包、错误脱敏、推理能力与默认强度，以及普通内容原样保留。
- Playwright 使用已安装的 Microsoft Edge，检查渠道发现与选择、模型搜索筛选、推理设置、圆角列表键盘操作、设置、验证、恢复及页面无障碍。
- 此机器的 Edge 对部分 Vite 模块返回空 204，最终浏览器测试使用 `VELA_E2E_LOCAL_PROXY=1`，仅将 1420 端口的静态 GET 资源经测试请求客户端转交；普通测试默认关闭此选项。最终原生程序直接加载安装包内资源，验证时未运行 Vite。
- `scripts/native-smoke-v2.mjs <exe>` 在隔离 `CODEX_HOME` / `VELA_DATA_DIR` 中使用真实 Tauri IPC、Windows 凭据和两个本机 mock 服务，验证完整元数据与路由流程。仅使用合成 Key。
- `scripts/official-models-smoke.mjs <official-cli.exe>` 验证官方客户端对等价目录、默认值及实际请求 effort 的处理；不等同于真实第三方推理服务验证。
- `scripts/updater-smoke.mjs <signed-installer.exe>` 使用实际更新插件验证正常、篡改、版本错配安装包；`--public` 验证公开 GitHub 更新源，只下载和验签，不运行安装器。
- `scripts/native-smoke.mjs` 保留为 0.1 直连流程的历史验收脚本。

本机模拟服务与官方模型目录读取测试不能替代真实第三方服务验收。官方桌面版首次未登录引导、真实额度口径、不同模型的复杂工具任务和干净 Windows 虚拟机安装仍需按实际服务商与客户端版本验证。
